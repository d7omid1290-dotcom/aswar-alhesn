# أسوار الحصن 🏰 (الإصدار 2)

لعبة مسابقات جماعية عربية: كل فريق يوزّع عناصر حصنه سرًّا على خانات مرقّمة، والمقدم يطرح الأسئلة، ومن يجيب يختار رقمًا من حصن خصمه فتنطلق قذيفة وتظهر النتيجة بشكل كبير على الشاشة.

## التقنيات

| المجال | الأداة |
|---|---|
| الإطار | Next.js 15 (App Router) + React 19 + TypeScript |
| الواجهة | Tailwind CSS 4 + مكونات shadcn/ui (Radix) + الوضعين الداكن والفاتح |
| ساحة المعركة | Phaser 3: قلاع إيزومترية، قذائف بمسار قوسي، انفجارات جزيئات، اهتزاز الكاميرا |
| الحركة | Motion: انتقالات الواجهات وبطاقة نتيجة الضربة وعدّاد النقاط |
| الصوت | Howler.js (المؤثرات مولّدة في `public/sfx` عبر `scripts/gen-sfx.mjs`) |
| الأصول | رسومات SVG إيزومترية في `public/assets` (الملك، الفارس، المدفعية، الحارس، السوق، الفخ، الأبراج، البلاط) |
| البيانات | Supabase PostgreSQL: الغرف والأسئلة والنتائج |
| الاتصال اللحظي | Supabase Realtime (أو SSE من خادم Next عند التشغيل المحلي) |
| الاختبار | Vitest لقواعد اللعبة + Playwright لمباراة كاملة بين شاشة المقدم والجوال |
| التثبيت كتطبيق | PWA: ملف manifest وعامل خدمة وأيقونات |

## الأمان ومنع التلاعب

- **الخادم هو المرجع الوحيد**: المتصفح يرسل «نوايا» فقط (اضرب الخانة ٧)، والخادم يتحقق منها (zod) ويحسب النقاط.
- **التوزيع السري**: كل جوال يستلم نسخة مفلترة من الحالة؛ لا يرى من حصون الخصوم إلا الخانات المضروبة، ولا رموز دخول الفرق، ولا الإجابة قبل كشفها.
- **الصلاحيات**: مفتاح المقدم يُخزَّن مُشفَّرًا (SHA-256)، وكل فريق له رمز دخول من ٦ أحرف. الفريق لا يستطيع إلا توزيع حصنه وتغيير اسمه والضرب في دوره.
- **حماية من التخمين**: حد لمحاولات الدخول الخاطئة لكل عنوان IP.
- **قاعدة البيانات**: RLS مفعّل على كل الجداول بلا سياسات، فلا يقرأ المتصفح أي جدول مباشرة؛ إشعارات Realtime تحمل رقم الإصدار فقط.
- **التزامن**: حفظ متفائل برقم إصدار يمنع تضارب حركتين في اللحظة نفسها.

## التشغيل المحلي

يحتاج Node.js 20 أو أحدث.

```bash
npm install
npm run dev          # http://localhost:3000
```

بدون إعداد Supabase تعمل اللعبة بذاكرة الخادم وبث SSE، وهذا يكفي للتجربة ولأي استضافة Node واحدة.
لكي تدخل الجوالات من نفس الشبكة افتح شاشة المقدم بعنوان الجهاز على الشبكة (مثل `http://192.168.1.20:3000/host`).

الصفحات:
- `/` الصفحة الرئيسية
- `/host` شاشة المقدم (غرفة مع الجوالات)
- `/host?local=1` وضع الشاشة الواحدة بلا جوالات
- `/play` جوال الفريق

## تفعيل Supabase

1. أنشئ مشروعًا في Supabase.
2. من SQL Editor شغّل `supabase/migrations/0001_init.sql` و`0002_server_rpc.sql` ثم `supabase/seed.sql` (٧٤ سؤالًا أوليًا).
3. من Realtime › Settings تأكد أن القنوات العامة مسموحة (الإشعارات لا تحمل بيانات سرية).
4. انسخ `.env.example` إلى `.env.local` واملأ:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - إما `SUPABASE_SERVICE_ROLE_KEY` (سري: على الخادم فقط)
   - أو `SUPABASE_DB_SECRET`: نص عشوائي طويل تحفظه أيضًا في القاعدة:
     `insert into private.config values ('server_secret', '...');`
     بهذا يعمل الخادم بالمفتاح العام عبر دوال `aswar_*` المحمية بالسر، والجداول تبقى مقفلة.

الأسئلة تُقرأ من جدول `questions` (عمود `active` لإخفاء سؤال)، والنتائج تُحفظ في `results` عند نهاية كل معركة.

## النشر على Vercel

1. ارفع المستودع إلى GitHub واستورده في Vercel.
2. أضف متغيرات Supabase في إعدادات المشروع. **مطلوبة على Vercel** لأن دوال Vercel لا تحتفظ بالذاكرة بين الطلبات.
3. Deploy.

بديل بلا Supabase: أي استضافة تشغّل `npm run build && npm start` كخادم واحد دائم (Render أو Railway أو Fly.io).

npm run build && npm run test:e2e   # مباراة كاملة في المتصفح (Playwright)

## هيكل المشروع

```
src/lib/game/        قواعد اللعبة (engine.ts) والأنواع وبنك الأسئلة
src/lib/server/      الغرف والصلاحيات وSupabase والتحقق من الحركات
src/lib/client/      الاتصال اللحظي ووضع الشاشة الواحدة
src/components/game/ شاشة المقدم، جوال الفريق، ساحة Phaser، بطاقة الضربة
src/components/ui/   مكونات shadcn/ui
src/app/api/rooms/   واجهات API
public/assets/       الرسومات الإيزومترية (SVG)
public/sfx/          المؤثرات الصوتية
supabase/            قاعدة البيانات والبيانات الأولية
tests/e2e/           اختبارات Playwright
```

## إضافة أسئلة

- من داخل اللعبة: «أسئلتي الخاصة» في الإعدادات.
- دائمًا: أضف صفوفًا في جدول `questions` في Supabase، أو في `src/lib/game/questions.ts` ثم `node scripts/seed-sql.mjs`.
